# Routing efficiency work (local, not published)

Base: published `cfb2be02bba544e1c7b1192915fcd9ec4985dd91`. The initial bounded baseline ran only after targeted process inspection found no Ant World, cargo/rustc, Vitest, Playwright, tsx or Speed Reader test process. Chrome and iCloud/File Provider activity remained substantial; no processes were stopped. One warmup and five samples per fixture on Node v25.9.0. Median full solve: synthetic 512-node explicit circle 4.58 ms; saved Vancouver legacy search 124.62 ms. The latter's median JSON parse/clone/standalone graph construction were approximately 4.46/8.68/6.53 ms. Graph construction is already included in full solve; these stages must not be added twice. These are local fixture observations, not public-service/network timing claims. Full baseline samples: `/tmp/gc-routing-baseline.json`; baseline source archived at `/tmp/gc-baseline-cfb2be0`.

Implemented locally:

- Raw OSM cache retains at most three complete responses and 24 MiB of encoded-response bytes for 15 minutes from original fetch. Exact queries or conservatively containing query disks can reuse the complete raw dataset. Rounded query centers and a one-meter containment guard prevent edge-rounding reuse. Ways, all geometry nodes and all returned restrictions remain intact; prepared graphs clip to each exact requested boundary. No partial-area merge, retry, provider change or cooldown bypass.
- A successful worker survives for later generations. Each dataset is cloned once per worker ownership period; repeated requests send settings and dataset ID only. Two prepared boundary/preference graphs are retained, capped at 250,000 directed edges in total. Start/tolerance changes reuse graph preparation but rerun snapping, returnability and path search. Different dataset, boundary, surface or road preference cannot reuse an incompatible graph.
- Cancel terminates the worker immediately and discards its cache. Request IDs and abort checks reject old replies; a replacement worker receives the dataset again. Crash handling resets ownership. No cooperative-cancellation delay or new shared-memory/security requirement.
- Candidate node projections, geodesic radial edge costs and edge/state string keys are reused without changing formulas, candidate order, scoring, acceptance or geometry. Per-solve projection/radial caches are bounded.
- The latest `performance.getEntriesByName('great-circle-generation')[0].detail` records download/parse/bytes/cache state, synchronous postMessage transfer, graph preparation, snapping/component, path search, expansion/projection counts and total generation time. Only the latest entry remains; no location/settings values are logged or persisted.

Validation so far: typecheck and 38 small deterministic tests pass, including complete coverage/LRU/expiry, preferences/boundary invalidation, preserved restriction relations, graph clipping and exact baseline GPX SHA-256 parity on both the 512-node circle and frozen actual OSM snapshot. The compressed, attributed public OSM fixture is committed under `tests/data/`; tests do not fetch it. Worker reuse/cancel/stale/crash browser regressions passed on desktop and phone. The full final revision passed 42 deterministic tests, the typechecked build and 37 applicable browser cases (seven phone-only desktop copies skipped). The separately released comparison slot was checked for Ant/build/browser jobs before timing; none were found. Chrome remained active; no processes were stopped. Nothing on this feature branch has been pushed or deployed.

## Paired offline comparison

Measured source: `f9ddd8d6c422f0c36086e1473476147ae72cdeaf`; published solver baseline: `cfb2be02bba544e1c7b1192915fcd9ec4985dd91`. Node v25.9.0; one excluded warm-up per mode, five interleaved samples per mode with rotating order. Cold creates/prepares a new graph each call; warm retains its dataset and prepared graph. Timings cover solving, excluding parse, worker startup/transfer, export hashing and **all network latency**. These small fixtures and five samples are indicative, not universal or statistically robust performance claims. The initial baseline above had different background activity; use the paired baseline column for comparisons.

| Fixture | Paired baseline median | Optimized cold median | Optimized warm median |
| --- | ---: | ---: | ---: |
| 512-node explicit circle | 3.91 ms | 2.81 ms | 1.90 ms |
| Frozen Vancouver 1 km, legacy search | 111.16 ms | 60.29 ms | 47.24 ms |

Every warmup and measured result matched the exact published-baseline GPX SHA-256. Geometry length/point count/candidate count stayed identical: ring 6,283.145858 m / 513 points / six candidates; Vancouver 3,264.457950 m / 199 points / 28 candidates. For Vancouver, median prepared-graph stage was 7.04 ms cold versus 0.0042 ms warm; each still recomputed snapping/returnability and searched 109,127 states. The explicit circle projects 512 nodes once across six candidates. Full samples, hashes and timings: [routing-comparison-results.json](routing-comparison-results.json).

Browser regressions separately verified one worker/dataset transfer across repeated successful generations, prepared-graph reuse for a new start, reuse of a larger complete OSM response for a smaller requested area with fresh graph clipping, zero added map request for those cache hits, and immediate worker termination/replacement on cancel/crash with late replies ignored. These request-count assertions use mocks; no public-service latency speedup is claimed.

Reproduce only in a coordinated quiet timing window: archive the published baseline (`git archive cfb2be0`) into a separate directory, make the locked dependencies available there, then run `npm run benchmark:routes -- --baseline /absolute/path/to/archive`. The harness verifies the baseline solver source hash and fixture hashes, bounds sample count, rejects any GPX difference and writes `/tmp/great-circle-routing-comparison.json`. Installation/build/tests do not run it automatically. Timing was released immediately after the bounded run; no commands remain active. Performance and the subsequent [radius/map refinements](radius-map-refinement.md) remain local pending publication approval.
